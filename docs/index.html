Auth, in order

Read only Part A until it is clear. Then B. Then C. Do not mix them in an interview opening.

Part A — How login works

Goal of login: prove “this email owns this password.” Nothing else.

  1. Browser. User submits the form on Login.jsx. React sends POST /api/auth/login with JSON { "email": "...", "password": "..." }. There is no token on this request. Login is public.
  2. API. Express looks up that email in MongoDB. If missing → 400, same message as a wrong password.
  3. Password check. Mongo stores a bcrypt hash, not the real password. bcrypt.compare(typed, hash) is true or false. False → 400.
  4. Extra rules (still login, not JWT yet). Resident + pending → 403 (admin has not approved). inactive → 403.
  5. Success body. API returns two things: a user object (no password) and a token string. How that string is built is Part B.
  6. Browser after success. login(token, user) saves the token as kutumb_token in localStorage, puts user in React state, then navigate('/app').

One sentence to say: “Login is bcrypt against Mongo. If it passes, the API hands back a JWT and the React app stores it.”

Part B — How the JWT works

The token is not the password. It is a signed ID card the API created after login succeeded.

  1. Create. jwt.sign({ id: user._id, role: user.role }, process.env.JWT_SECRET, { expiresIn: '7d' }). Payload is only id and role. Secret is on the server. Expiry 7 days.
  2. Shape. Three Base64 parts: header.payload.signature. Anyone can decode the payload (it is not encryption). The signature is the lock.
  3. Trust. Later, jwt.verify(token, JWT_SECRET). If someone changes role to admin in the payload, the signature no longer matches → 401.
  4. Use. api.js reads kutumb_token and sends Authorization: Bearer <token> on every call except login/register/forgot.
  5. Middleware auth.js: verify JWT → load that User from Mongo → req.user. Routes then filter data (resident sees own bills) or allowRoles('admin').

One sentence to say: “JWT is a signed note of user id and role. The password is not inside it. The server verifies the signature with JWT_SECRET.”

Part C — Other scenarios (only after A and B)

Refresh. React state is gone. Token is still in localStorage. App calls GET /api/users/me with Bearer. Verify JWT, return user. Bad/expired token → delete kutumb_token. Password is not sent again.

Logout. Delete kutumb_token, user = null. Next request has no Bearer. We do not blacklist tokens (demo).

Register. Creates resident pending. No token. They must complete Part A after admin approves.

Guard (UI). No user → /login. Wrong role on a URL → /app. This only hides pages.

allowRoles (API). Real lock. A resident JWT cannot hit POST /api/bills/generate.

localStorage vs cookies. We used localStorage because it is simple. XSS could steal the token; production often uses httpOnly cookies.

Live vs Past lists

Default view is only unfinished work so a month of data does not bury the courtyard. StackFilter.jsx splits on the client. Past needs a month pick.

  • Complaints — live if not resolved.
  • Bills — live if not paid. Admin sees owner name + flat.
  • Visitors — live if pre-approved or entered (still inside, even if 5 days old).
  • Bookings — live if pending, or approved with date ≥ today.
  • Notices — pinned or last 30 days.
  • Emergencies — live if active.

  2. Pick a future day on the calendar. Request start–end.
  3. API rejects overlapping pending/approved slots (same facility + date + overlapping HH:mm).
  4. Resident booking is pending; admin approves or rejects. Admin booking is auto-approved.

6. SOS

Likely interview questions (frontend)

Why React + Vite, not Next.js? Course stack was SPA + separate API. Vite builds static files for Vercel. The Express server on Render is the only backend.

Why no Redux / Context everywhere? Auth is one context. Each page loads its list with useState + useEffect. A global store is extra for this size.

Why fetch, not Axios? One helper in api.js adds the JWT and parses JSON. Native fetch is enough.

How does the UI talk to the API? api('/complaints') becomes fetch(VITE_API_URL + '/api/complaints') with Authorization: Bearer <kutumb_token>. React never queries Mongo.

Where is the token stored? Why not cookies? localStorage key kutumb_token. Simple for a college demo. Honest follow-up: XSS can steal it; production often uses httpOnly cookies.

What happens on refresh? React state is gone. Token is still in localStorage. AuthContext calls GET /api/users/me. Bad or expired JWT → delete token, send to login.

Guard vs hiding the sidebar — is that security? No. Guard only stops the wrong role seeing a page. Real lock is allowRoles on the API. Always say both.

How does each role get a different menu? NAV object in Layout.jsx. After login, NAV[user.role] draws the links. Resident never sees Residents or Gate in the sidebar.

How does login routing work? Public routes: landing, login, register, forgot, reset. Logged-in shell is /app/* wrapped in Layout. Wrong role on a URL → redirect to /app.

How do Live vs Past lists work? Client filter in StackFilter.jsx. Default = unfinished (unpaid bills, open complaints, guests still inside). Past needs a month so old data does not bury the courtyard.

How does Pay work on the screen? Resident taps Pay → POST /bills/:id/order returns { demo: true } → UI calls verify → bill shows paid. There is no checkout popup on this demo.

How is the visitor QR made? Pass page loads the guest from GET /visitors, draws the 6-digit passCode with qrcode.react.

How does SOS work in the UI? Resident button on the topbar posts POST /emergencies, then opens the emergencies list. Admin, security, and staff see Active until Mark handled.

How does forgot password work without email? Forgot page calls the API, which returns resetLink. The link is printed on screen. Open it, set a new password on Reset.jsx.

Why no TypeScript? Course and teammates used JS. Same language on client and server. Types would be nicer in a job project; this one shipped in JS.

If they open package.json and see extra libraries? chart.js is unused. A few server packages are leftover fallbacks this demo never turned on. Uploads are data URLs, pay is demo, reset link is on screen. Do not list those as the stack.

Auth middleware

server/middleware/auth.js

  1. Read Authorization: Bearer ….
  2. jwt.verify(token, JWT_SECRET) → { id, role }.
  3. Load user from Mongo (no password field). Put on req.user.
  4. allowRoles('admin') returns 403 if role does not match.

Passwords: bcryptjs hash on register/seed. Never store plain text. JWT expires in 7 days.

Backend workflows (what the API actually does)

Register / login

Register always creates role: resident, status: pending. Login rejects pending residents (403) and inactive accounts. Success: jwt.sign({ id, role }).

Auto-assign complaints

utils/staffJobs.js map:

plumbing → plumber electrical → electrician housekeeping → housekeeping lift → lift other/security → general

On POST, find first approved staff with that staffType. If found, set assignedTo and status assigned. Admin can POST /assign later. Staff GET uses staffJobFilter: jobs assigned to me, or unassigned in my trade.

Bills

Generate loops approved residents, skips duplicates for same month/year/type/title. maybeLateFee on GET: if past dueDate and not paid → overdue; maintenance gets lateFee 100. Pay in this project: order returns { demo: true }, then verify sets status paid and paidAt. There is no live payment gateway on the hosted demo.

Bookings

Clash: same facility + date + overlapping start/end among pending/approved. Times compared as strings HH:mm. Past dates rejected.

Visitors

Create: random 6-digit passCode, status pre-approved. Enter/exit stamp entryAt / exitAt. Lookup: GET /visitors/pass/:code.

Forgot password

Random token stored as SHA-256 hash + 1 hour expiry. This demo does not send email. API returns resetLink (CLIENT_URL/reset-password/<token>). Forgot page prints that link.

Upload

Multer memory storage, 12MB. Buffer is turned into data:<mime>;base64,... and that string is saved on the document (complaint media, proof, notice attachments).

Seed + demo staff

npm run seed wipes the eight collections and creates demo users, facilities, and sample rows. On every API boot, ensureDemoStaff() adds housekeeping / lift / general staff if those emails are missing (so auto-assign still works even if seed was not re-run).

Likely interview questions (backend)

Why MongoDB not MySQL? Nested family/vehicles on the user document, flexible complaint comments, faster to ship a college MERN project. Relations still exist via ObjectId + populate.

What is Mongoose doing? Schemas, validation, and populate. Example: a bill stores resident: ObjectId; GET populates name, flat, phone so the receipt page does not need a second query from React.

Why bcrypt, not plain text or SHA? Register/seed hash with bcrypt.hash(password, 10). Login uses bcrypt.compare. Bcrypt is slow on purpose (salt + rounds) so a stolen DB is hard to brute-force. SHA is fast — that is a weakness for passwords.

Walk through JWT on the API. Login succeeds → jwt.sign({ id, role }, JWT_SECRET, { expiresIn: '7d' }). Later auth middleware: Bearer header → jwt.verify → load User without password → req.user. Payload is not encrypted; the signature is the lock.

Why load the user from Mongo after verify? Token only has id and role. We still need status, flat, staffType. If the account was deleted, verify would pass but findById fails → 401.

401 vs 403? 401 = not logged in or bad/expired token. 403 = logged in but wrong role or pending resident. Login: pending → 403. Missing Bearer → 401.

How do you stop a resident hitting admin APIs? JWT has role. allowRoles('admin') on generate bills, assign, pin notice, add member. UI hiding the menu is not enough. Also filter lists: resident GET bills/complaints/visitors is scoped to req.user._id.

How is a plumber auto-assigned? staffJobs.js maps category → staffType (plumbing → plumber). On POST complaint, User.findOne({ role: 'staff', status: 'approved', staffType }). First match gets assignedTo and status assigned. Admin can POST /assign later. Staff GET uses staffJobFilter: my jobs, or unassigned in my trade.

How are booking clashes stopped? Same facility + same date + status pending or approved. Times are HH:mm strings. Overlap if aStart < bEnd && bStart < aEnd. Past dates rejected. Resident starts pending; admin starts approved.

How do bills and late fees work? Admin generate: one bill per approved resident, skip duplicate month/year/type/title. On GET, maybeLateFee: unpaid and past dueDate → overdue; maintenance adds ₹100 lateFee. Pay: order returns { demo: true }; verify sets paid + paidAt.

How does the gate pass work on the API? POST visitor makes a random 6-digit passCode, status pre-approved. Security GET /visitors/pass/:code, then enter stamps entryAt, exit stamps exitAt. Still-inside guests stay entered until exit.

Forgot password without email? Random token, store SHA-256 hash + 1 hour expiry (raw token is not in Mongo). Same success message whether the email exists (no leak). This demo returns resetLink. Reset finds unexpired hash, bcrypts the new password, clears reset fields.

Where do photos live? Multer memory, 12MB. Buffer → data:<mime>;base64,... string on the document (complaint media, proof, notice attachments). JSON limit is 15mb in index.js so those strings fit.

What is CORS? Browser blocks JS on vercel.app from calling onrender.com unless the API sends Access-Control-Allow-Origin matching CLIENT_URL (and localhost for dev).

Which routes are public? Only health GET /, register, login, forgot-password, reset-password. Everything under the other /api routers needs JWT.

Why seed locally for Render? Free Render has no Shell. Seed writes to the same Atlas DB the API uses. On every boot, ensureDemoStaff() adds extra trades if those emails are missing so auto-assign still works.

Why does the first load take 50s? Free Render spins down. First request wakes the Node process.

Do you blacklist JWTs on logout? No. Logout only deletes kutumb_token in the browser. Token stays valid until 7-day expiry. Honest: a stolen token works until then; industry often uses short access tokens + refresh, or httpOnly cookies.

Indexes / uniqueness? User email is unique. Duplicate register → 400. Bills skip duplicates in generate by querying existing month/year/type. No extra compound indexes — fine for a college dataset, say that if they ask.
